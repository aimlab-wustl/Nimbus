# FPGA decoders for the rotated surface code

This folder holds the RTL, generators, simulation testbenches, Vivado build scripts and PYNQ host code of the two FPGA
decoders in the paper. Both run parallel tempering (replica exchange) on the constrained Ising formulation of
surface-code decoding, on an RFSoC 4x2 board (Xilinx XCZU48DR-2).

| Mode | What it decodes | Core | Board design | Bit-exact software model |
|---|---|---|---|---|
| One syndrome per shot | one syndrome of code-capacity depolarizing noise per shot; maximum-likelihood class from the occupancy of the beta = 1 replica, plus the minimum-energy class | `pt_top` (`rtl/pt_top.sv`, generated `pt_core.sv`) | `pt_board` (AXI4-Lite slave, shot and result memories, batch controller) | `nimbus.decoding.one_shot` |
| Real time | a syndrome stream of the phenomenological (measurement-error) memory experiment, in sliding windows of 2d rounds that commit d rounds each | `ptw_top` (`rtl/ptw_top.sv`, generated `ptw_core.sv`) | `ptw_board` (streaming wrapper: round timer, syndrome ring, window state machine, record memory) | `nimbus.decoding.real_time` |

The RTL is bit-exact with the software models: for the same tables, seeds and syndromes, every replica's state, energy and
class after every move cycle (one syndrome per shot) or sweep (real time), and every decision, are identical. The xsim
testbenches check this, and the host tools check it again on the board's results.

The real-time generator flags all add `--p 0.04 --B 16 --K 1 --bmin 0.1`. Real-time layout flags: `--k` slabs (the window
is swept in k slices, one at a time), `--lram` clause literals in LUT RAM (k >= 5), `--rs` replicas time-shared per engine,
`--cs 1` C-slow (3-stage) move loop, `--srl 1` shift-register lane generators, `--swp 1` registered swap decision, `--fo 0`
no replicated swap enables.

Board clock: PYNQ makes PL clock 0 only in steps of the board's 1500 MHz PLL. Where the build's PL clock 0 could not be set
exactly, the driver set the nearest lower value (93.75 MHz for the one-syndrome-per-shot d = 3 and d = 5 designs, 88.2 MHz
for the real-time d = 9 design), and the decoder clock (an MMCM output of PL clock 0) scaled with it. The driver measures
the decoder clock and refuses to run above the routed Fmax of the build.

**Original bitstreams.** The 12 bitstreams of the table (`.bit` and `.hwh`, plus the build `.json` with all build
parameters, clocks, timing and utilization) are provided as the release download `nimbus_bitstreams.zip`
(https://github.com/aimlab-wustl/Nimbus/releases/tag/v1.0), named `one_shot_d<d>` and `real_time_d<d>`, with a
`MANIFEST.txt` that maps each file to its table row and gives its SHA-256. The same zip is archived in the Zenodo
record [10.5281/zenodo.24182700](https://doi.org/10.5281/zenodo.24182700). With them, no Vivado installation is needed to
run the decoders.

**Rebuilding.** A few RTL files changed after some of the builds, to fix bugs that do not change the decoding of the
published designs: the swap-threshold refill of `pt_top.sv` (number of refill lanes; it matters only at 40 or more
replicas, and the d = 11 design was built with the fix), the width of a window-preparation counter in `ptw_top.sv`
(it matters only for the d = 11 real-time layout, built with the fix), and an optional registered swap path in
`ptw_top.sv` (off except for d = 11). The 12 cores in `cores/` are exactly those of the builds (the generators in `gen/`
reproduce them; the `ptw_info.json` of the four smaller real-time cores lacks the later field `"swp": 0`). A rebuild from
this RTL therefore gives the same decoding, bit for bit, but placement, routing and LUT counts can differ slightly from
Table S5.

## Generate a core

```
python hardware/gen/gen_pt.py --d 7 --NS 64 --K 2 --B 16 --p 0.12 --bmin 0.1 --out my_cores/pt_d7_ns64
python hardware/gen/gen_sizes.py 3x16 5x16 7x64 9x56 11x40 13x32 15x24 --out-dir my_cores     # all seven
python hardware/gen/gen_ptw.py --d 9 --R 24 --k 9 --lram --rs 3 --cs 1 --p 0.04 --B 16 --K 1 --bmin 0.1 --out my_cores/ptw_d9
```

The generators import `nimbus.decoding` (the move sets, colorings, chains and power-on tables come from the software
model). `--p` sets only the power-on tables. `gen_lut.py` regenerates `rtl/tp_lut_rom.sv` (U = 12, LF = 16).

## Simulate (xsim)

Each `run_*.sh` script generates one test case (RTL, seeds, syndromes and the software model's expected values), compiles
it with xvlog / xelab and runs xsim; each `suite_*.sh` runs a list of cases and prints one `RESULT: PASS|FAIL` line per
case. Set `VIVADO_BIN` to the Vivado `bin` folder (or put it on PATH) and `PYTHON` to the interpreter with `nimbus`
installed. On Windows, run the scripts from Git Bash.

```
export VIVADO_BIN=/opt/Xilinx/Vivado/2024.2/bin PYTHON=python
bash hardware/sim/suite_pt.sh          # one syndrome per shot core: every replica after every move cycle, 18 cases
bash hardware/sim/suite_board.sh       # pt_board: a driver session replayed through AXI4-Lite, two clocks, 4 cases
bash hardware/sim/suite_ptw.sh         # real-time core: every sweep record and every commit record, 20 cases
bash hardware/sim/suite_ptw_board.sh   # ptw_board: timed, throughput and too-tight batches, 6 cases
bash hardware/sim/run_pt.sh 5 8 64 6 2 16 0.12 5 4 24      # one case: d NS nsw shots K B p seed gmin th32
```

The core cases switch the runtime tables in the middle of a stream (with RECALC) and cover early stopping, every real-time
layout (parallel, flip-flop slabs, LUT-RAM slabs, time-shared and C-slow engines, registered swap) at reduced replica
counts and budgets. The board cases record the bus traffic of the PYNQ driver against the register-level mock and replay it
through AXI4-Lite on `pt_board_top` / `ptw_board_top` (100 MHz AXI clock, unrelated decoder clock), comparing every read,
including the cycle counts of the cycle model. Outputs go to `hardware/sim/work/`.

Python tests (no board, no Vivado):

```
python -m pytest tests/test_hw_pt_board.py tests/test_hw_ptw_board.py
```

## Build a bitstream

```
vivado -mode batch -nojournal -source hardware/build/build_pt_board.tcl \
       -tclargs gen=pt_d7_ns64 d=7 NS=64 K=2 target=rfsoc4x2 dec_mhz=250
vivado -mode batch -nojournal -source hardware/build/build_ptw_board.tcl \
       -tclargs gen=ptw_d9_r24_k9l_rs3_cs d=9 target=rfsoc4x2 dec_mhz=265 strategy=Performance_Explore
```

Keys are `key=value` (or `key value`) pairs; the build keys of each published design are in the table above. `gen=<name>`
takes the core from `hardware/cores/<name>` (or any folder); `gen=generate` (the default) runs the generator first, with the
interpreter given by `python=` or `$PT_PYTHON`. Other keys: `target` (`rfsoc4x2`, or `zu7ev` to test the flow on a part the
free Vivado edition covers), `dec_mhz` (decoder clock), `axi_mhz` (100), `pl0_board` (PL clock 0 as the board makes it;
100 for `rfsoc4x2`), `strategy` (implementation strategy), `jobs`, `out`, `name`, `proj`, `stop` (`bd`, `synth` or
`bitstream`).

The block design has the Zynq UltraScale+ processing system, a SmartConnect, a clocking wizard (decoder clock from PL clock
0), two reset blocks and the board wrapper as a module reference; the design uses no package pins. Outputs in
`hardware/build/out/<name>/` (or `out=`): `<name>.bit` and `<name>.hwh` (PYNQ needs both, with the same base name),
`<name>.xsa`, `<name>.json` (build parameters, git commit, Vivado version, clocks, slack per clock, utilization), `reports/`,
and `deploy/` with what the board needs. A build takes about 1 to 4 hours for the large designs.

Clocking: the AXI side runs at 100 MHz (PL clock 0) and the decoder at its own clock from an MMCM. The memories are
dual-clock block RAMs and register accesses cross through a request/acknowledge tunnel, so all cycle counters run on the
decoder clock and the measured latency does not depend on the AXI clock. PYNQ applies the `.hwh` clock dividers to the
board's 1500 MHz PLL, not to the PLL Vivado assumes; the build therefore scales the MMCM request so that the decoder runs at
`dec_mhz` when PL clock 0 is `pl0_board`, analyzes timing at that clock, and records `pl0_board_mhz` in the `.json`, from
which the driver sets PL clock 0.

## Run on the board

Copy `<name>.bit`, `<name>.hwh`, `<name>.json` and the driver (`host/pt_board.py` or `host/ptw_board.py`; for power also
`pt_power.py` / `ptw_power.py`) to one folder on the board. Run the board commands with the PYNQ environment sourced (as
root: `source /etc/profile.d/pynq_venv.sh` and `source /etc/profile.d/xrt_setup.sh`), and only one process that loads
overlays at a time.

One syndrome per shot:

```
python hardware/host/pt_host.py make-shots --d 7 --p 0.15 --shots 2000 --seed 7 --out shots_d7_p0.15.npz      # host
python3 pt_board.py --bit one_shot_d7.bit --shots shots_d7_p0.15.npz --p 0.15 --nsw 1024 --seed 1 --out d7_fixed.npz   # board
python3 pt_board.py --bit one_shot_d7.bit --shots shots_d7_p0.15.npz --p 0.15 --nsw 4096 --gmin 64 --th32 29 --seed 1 --out d7_es.npz
python hardware/host/pt_host.py check --res d7_fixed.npz --max 300                                            # host
```

`make-shots` stores the syndromes and, for the logical error rate, whether each of the four logical classes fails.
`check` rebuilds the software model with the tables, seed, budget and early-stop settings stored in the result file, runs
the same shots back to back on one generator stream (as the board does) and compares, per shot, both classes, the sweeps,
the minimum energy, the four class counts and the cycle count of the cycle model; exit code 0 means all equal.
The shot count of each batch must be a multiple of 4 (the driver raises `ValueError` otherwise); use a shot file whose length
and `--batch` are multiples of 4.
`pt_es_grid.py` reruns a shot file on the board for a list of early-stop settings.

Bring-up order: `PTBoard.from_overlay` reads ID and CFG0-5 (a wrong ID means a wrong bitstream or address);
`measure_clock()` checks the decoder clock against the build; then a short run at a small budget and `check`; then
`set_noise` with another p, without reseeding, and `check` again (this exercises RECALC on the board).

Real time:

```
python hardware/host/ptw_host.py make-shots --d 7 --p 0.03 --shots 1000 --seed 7 --out shots_ptw_d7_p0.03.npz
python3 ptw_board.py --bit real_time_d7.bit --shots shots_ptw_d7_p0.03.npz --p 0.03 --nsw 4096 --batch 25 --out d7_thr.npz
python3 ptw_board.py --bit real_time_d7.bit --shots shots_ptw_d7_p0.03.npz --p 0.03 --nsw 4096 --batch 25 --tround-us 1000 --out d7_rt.npz
python hardware/host/ptw_host.py check --res d7_thr.npz --max 300 --workers 12     # bit-exact, cycle model, LER, timing
python hardware/host/ptw_host.py same --a d7_rt.npz --b d7_thr.npz                # real-time run: identical decisions
python3 ptw_power.py real_time_d7.bit shots_ptw_d7_p0.03.npz 0.03 4096 --batch 25  # core-rail power plateau
```

Without `--tround-us` the round timer releases all rounds at once (throughput); with it, one round every T_ROUND, and the
records carry trigger, take and commit times and the number of missed deadlines. Each batch is reseeded with seed + batch
index, so `check` verifies batches in parallel. `pt_power.py` and `ptw_power.py` read the core rail (VCCINT, PMBus
`VCCp0V85`) every 0.1 s while batches run and report the idle and decoding plateaus.

## Register maps and record layouts

### `pt_board` (ID 0x50540200)

Address window 256 KB: registers at 0x00000-0x00FFF (decoder clock domain, through the tunnel), syndrome memory at
0x10000-0x1FFFF, result memory at 0x20000-0x3FFFF. Writes are full 32-bit words.

| Offset | Name | Access | Contents |
|---|---|---|---|
| 0x000 | CTRL | W | bit 0 START (batch of NSHOT shots), bit 1 FILL (after seeding), bit 2 RECALC (after a theta change), bit 3 ABORT, bit 8 IRQ_EN |
| 0x004 | STATUS | R | bit 0 ready, bit 1 batch busy, bit 2 done (until the next START), bit 3 decoder busy, bit 4 decoder ready |
| 0x008 | NSW | RW | sweep budget per shot, a power of two >= 2 (the cap with early stopping) |
| 0x00C | ES_GMIN | RW | early stop from this many sweeps (power of two, >= K); 0 = off |
| 0x010 | ES_TH | RW | stop when 32 x (largest class count) >= ES_TH x (block total); 1..63 |
| 0x014 | NSHOT | RW | shots in the next batch, 1..CFG4 |
| 0x018 | SHOT_DONE | R | shots finished in the current batch |
| 0x01C | SEED_CTRL | W | bit 1 push the staged lane seed bits into history A, bit 2 into history B |
| 0x020 | THR_COMMIT | W | write the staged threshold row into row (label) = data of every replica's table |
| 0x024 | ID | R | 0x50540200 |
| 0x028-0x03C | CFG0-CFG5 | R | CFG0 {NS, B, K, KM}; CFG1 {n, M}; CFG2 {TW, EW, colors, LW}; CFG3 {SYN_AW, RES_AW, log2 words per shot, USW}; CFG4 shots per batch; CFG5 {Lmax B, Lmax} |
| 0x040 / 0x044 | FRC_LO / FRC_HI | R | free-running decoder-clock counter (reading LO latches HI) |
| 0x048-0x054 | T_START / T_END | R | FRC at the batch start and when the last record was written |
| 0x080 + 4 j | SEED_LANE[j] | W | lane seed bits, bit i of word j = replica 32 j + i; writing the last word shifts them in |
| 0x0A0 + 4 j | SEED_SWAP[j] | W | swap-generator seed bits, one per pair; writing the last word shifts |
| 0x200 + 4 k | THR_STAGE[k] | RW | staged threshold T[.][k + 1] (B bits), k = 0..KM - 1 |
| 0x400 + 4 t | THETA[t] | W | swap constant of pair t (20 bits), t = 0..NS - 2 |

Syndrome memory: shot s, word w at byte 0x10000 + 4 (s 2^L + w), L = CFG3[15:8]; bit j of word w = syndrome bit 32 w + j
(X checks first). Result memory, 8 words per shot at 0x20000 + 32 s: w0 {minimum energy [31:16], stopped early [4],
minimum-energy class [3:2], ML class [1:0]}; w1 sweeps run; w2 cycles from taking the syndrome to the first move; w3 cycles
from the first move to the decision; w4-w6 the four class counts of the deciding block (20 bits each, count 0 at bit 0);
w7 FRC[31:0] at the decision. The on-chip latency per shot is w2 + w3 + 2 decoder cycles; it excludes host traffic (the
batch controller prefetches the next syndrome while the current shot decodes).

Runtime tables: lane thresholds T[t][k] = floor(2^B exp(-beta_t w3 k)) (label t, energy change k = 1..d; they must not
increase with k) and swap constants theta_t = round(2^12 / ((beta_t - beta_{t+1}) w3)). The driver computes them from p
and the ladder (`set_noise`) with the arithmetic of `nimbus.decoding.one_shot.make_tables`, and stores them with every result
file. After a theta change, RECALC recomputes the pre-drawn swap thresholds from the same uniforms, so the random streams
stay those of the software model.

Cycle model (`cycle_model` in `pt_board.py`, validated per shot in xsim), TR = ceil(log2(NS) / 2):
fixed budget n: 5 + 6 n + 4 (floor((n - 1) / K) - c) + 8 c + TR + 3, c = early-stop checkpoints passed (powers of two in
[gmin, n)); early stop at checkpoint g: 5 + 6 g + 4 (g / K - 1 - c) + 8 (c + 1) + TR - 2, c = checkpoints before g.

### `ptw_board` (ID 0x50545701)

One batch = S shots of N + 1 = 4d + 1 rounds (the last one the error-free round), preloaded into the shot memory (round k
of the batch at word k 2^WPL). The round timer makes round k due at T_START + (k + 1) T_ROUND + 1 decoder cycles
(T_ROUND = 0: all at once); due rounds enter a syndrome ring of 3d + 1 rows. Window w of a shot (rounds [w d, w d + 2d);
the final window [2d, 4d) plus the error-free round) is triggered when its last round is written; the window state machine
assembles it from the ring and hands it to `ptw_top`. The deadline of a window is the trigger of the next one; MISSES
counts triggers that arrive before the previous window committed. The generators run on across windows, shots and batches
until reseeded (`nimbus.decoding.real_time.decode_batch` models this stream).

Registers: 0x000 CTRL (W: 1 START, 2 FILL, 4 RECALC, 8 ABORT, 0x100 IRQ enable), 0x004 STATUS (R: 1 ready, 2 batch busy,
4 batch done, 8 core busy, 16 core ready), 0x008 NSW (sweeps per window), 0x00C T_ROUND (decoder cycles), 0x010 NSHOT,
0x014 / 0x018 Wq / wq (12-bit fixed-point weights), 0x01C SEED_CTRL (W: bits 0-7 push A per bank, 8-15 push B per bank,
16-23 local replica), 0x020 THR_COMMIT (W: label), 0x024 ID, 0x028-0x03C CFG0-5, 0x040 / 0x044 FRC, 0x048-0x054 T_START /
T_END, 0x058 MISSES, 0x05C LATE_ROUNDS, 0x060 RELEASED, 0x064 WIN_DONE, 0x068-0x070 CFG6-8, 0x074 TMODE (rank mode,
p < 1/28), 0x080 SEED_LANE, 0x084 SEED_SWAP, 0x200 + 4 k THR_STAGE[k], 0x400 + 4 t THETA[t]; result memory at 0x40000
(2^16 words), shot memory at 0x80000. CFG0 {R, B, K, ROWN}, CFG1 {d, TR, M2, NC}, CFG2 {TW, EW, LW, QW}, CFG3 {SYN_AW,
RES_AW, WPL, USW}, CFG4 shots per batch, CFG5 {NE, RS, NB, KS}, CFG6 {CSL, GAP_SW, LDC, KSL}, CFG7 {lanes of bank 1,
bank 0}, CFG8 {RD, NP, RB, WPR}.

Window record (16 words, 3 per shot, in commit order): w0 {shot [31:16], window [10:9], final [8], best class [7:6], ML
class [5:4], frame bits [3:2], ML frame bits of final windows [1:0]}; w1 best energy; w2-w5 class counts of the last sweep
block; w6-w9 sigma after the commit (up to 128 bits); w10-w11 trigger cycle; w12 take - trigger; w13 commit - take; w14
core cycles from take to commit; w15 lag of the trigger round behind its due time.

Cycle model (xsim and mock): cycles per window = nsw R_e k NC + GAP_SW floor((nsw - 1) / K) + max(LDC, 4) +
ceil(log2 R) + 2 CSL + 10, with R_e replicas per engine; commit - take = that + 1.

## Notes

- PL clock 0: PYNQ can make only some values from the board's PLL; `from_overlay` sets the highest value not above the
  build's `pl0_board_mhz` (from the `.json` next to the bitstream) and `measure_clock()` reports the decoder clock.
- Bulk MMIO copies: `pt_board.py` writes the syndrome block with one slice assignment to the memory-mapped array. The block
  must be a whole number of 16-byte groups, so the shot count of every batch must be a multiple of 4 (`run_batch` raises
  `ValueError` otherwise; with `run`, use a shot count and a `batch` that are multiples of 4). `ptw_board.py` pads its block
  writes to whole 16-byte groups and copies in chunks of 64 words.
- The board's root file system is small; the builds write compressed bitstreams.
